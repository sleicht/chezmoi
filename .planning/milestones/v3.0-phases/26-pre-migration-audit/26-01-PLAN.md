The runbook must contain these sections:

**Header:**
- Title: "Pre-Migration Audit Runbook"
- Purpose: Capture local state on the client Mac before switching from Dotbot to chezmoi
- Prerequisites: Access to the client Mac, the frozen `dotfiles-zsh` repo still present at its current location
- Output: An audit report saved to a temporary directory (`~/migration-audit/`)

**Procedure 1: List Dotbot Symlinks (AUDIT-01)**

Commands to enumerate all symlinks created by Dotbot:
1. Create output directory: `mkdir -p ~/migration-audit`
2. Find the Dotbot config file: `cat ~/dotfiles-zsh/install.conf.yaml` (or wherever the Dotbot repo lives -- note: the user should verify the actual path; common locations are `~/dotfiles-zsh`, `~/.dotfiles`, or `~/dotfiles`)
3. Parse the `link:` section to list all declared symlinks and their targets
4. Verify which symlinks actually exist on disk vs declared but broken:
   ```bash
   # Find all symlinks in $HOME pointing into the dotfiles repo
   find ~ -maxdepth 3 -type l -exec readlink -f {} \; 2>/dev/null | grep -i dotfiles | sort > ~/migration-audit/dotbot-symlinks.txt
   ```
5. Also check for symlinks in common config directories:
   ```bash
   find ~/.config -maxdepth 2 -type l 2>/dev/null >> ~/migration-audit/dotbot-symlinks.txt
   find ~/.ssh -type l 2>/dev/null >> ~/migration-audit/dotbot-symlinks.txt
   ```
6. Cross-reference with chezmoi's managed file list:
   ```bash
   chezmoi managed --exclude=dirs 2>/dev/null | sort > ~/migration-audit/chezmoi-managed.txt
   ```
   Note: chezmoi may not be installed yet on the client Mac. If not, the user can generate this list on the personal Mac instead and copy it over (or skip this step and do it in Phase 27 after bootstrap).
7. Output: `~/migration-audit/dotbot-symlinks.txt` -- one symlink per line with format `symlink -> target`

**Procedure 2: Identify Custom Scripts and Bins (AUDIT-02)**

Commands to find scripts the user has placed locally that are NOT tracked in either repo:
1. List all files in common bin directories:
   ```bash
   ls -la ~/bin/ 2>/dev/null > ~/migration-audit/custom-bins.txt
   ls -la ~/.local/bin/ 2>/dev/null >> ~/migration-audit/custom-bins.txt
   ```
2. For each file found, check if it exists in the dotfiles-zsh repo:
   ```bash
   # Compare ~/bin contents against dotfiles repo
   for f in ~/bin/*; do
     name=$(basename "$f")
     if [ ! -e ~/dotfiles-zsh/bin/"$name" ] && [ ! -e ~/dotfiles-zsh/scripts/"$name" ]; then
       echo "CUSTOM (not in dotfiles-zsh): $f"
     fi
   done > ~/migration-audit/untracked-scripts.txt
   ```
3. Also check if each file exists in the chezmoi source (run on personal Mac if needed):
   ```bash
   # On personal Mac: list chezmoi-managed bin files
   chezmoi managed | grep -E '(bin/|\.local/bin/)' > ~/migration-audit/chezmoi-bins.txt
   ```
4. Classify each custom script: preserve (copy to chezmoi), keep local (leave outside chezmoi), or discard
5. Output: `~/migration-audit/untracked-scripts.txt` -- files needing triage before migration

**Procedure 3: Capture Machine-Specific Environment Variables (AUDIT-03)**

Commands to capture env vars unique to the client Mac:
1. Capture the full environment in an interactive shell:
   ```bash
   env | sort > ~/migration-audit/client-env-full.txt
   ```
2. Capture shell-defined exports from zsh config files:
   ```bash
   grep -rn 'export ' ~/.zshrc ~/.zshenv ~/.profile ~/.zsh.d/ ~/dotfiles-zsh/ 2>/dev/null | sort -u > ~/migration-audit/client-exports.txt
   ```
3. Capture exports from private/local override files (these won't be in any repo):
   ```bash
   grep -rn 'export ' ~/.zsh.d.private/ ~/.zshrc.local ~/.profile.local 2>/dev/null | sort > ~/migration-audit/client-private-exports.txt
   ```
4. Identify env vars that differ from a baseline. The user should compare against the personal Mac:
   ```bash
   # On personal Mac: env | sort > /tmp/personal-env.txt
   # Copy to client Mac, then:
   diff ~/migration-audit/client-env-full.txt /tmp/personal-env.txt | grep '^<' > ~/migration-audit/client-unique-env.txt
   ```
5. Key variables to look for specifically:
   - `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` (corporate proxy settings)
   - `JAVA_HOME`, `ANDROID_HOME`, `FLUTTER_HOME` (SDK paths)
   - Company-specific vars (VPN configs, internal tool paths)
   - Any `*_TOKEN`, `*_KEY`, `*_SECRET` variables (note but DO NOT save values)
6. Output: `~/migration-audit/client-unique-env.txt` -- env vars unique to client Mac

**Procedure 4: Diff Drifted Configs (AUDIT-04)**

Commands to find configs that have been edited locally and drifted from the repo version:
1. Check git status in the dotfiles-zsh repo:
   ```bash
   cd ~/dotfiles-zsh  # or actual repo path
   git status > ~/migration-audit/dotfiles-drift-status.txt
   git diff > ~/migration-audit/dotfiles-drift-diff.txt
   ```
2. For files that are symlinks, compare the actual file content against the repo:
   ```bash
   # For each symlink managed by Dotbot, check if the target has been modified
   # (Dotbot symlinks point INTO the repo, so local edits change the repo working tree)
   git diff --stat >> ~/migration-audit/dotfiles-drift-status.txt
   ```
3. Check for files that exist at target locations but are NOT symlinks (manually placed copies that shadow what Dotbot would deploy):
   ```bash
   # Example: if ~/.gitconfig exists as a regular file instead of a symlink
   for target in ~/.gitconfig ~/.zshrc ~/.zshenv ~/.profile; do
     if [ -f "$target" ] && [ ! -L "$target" ]; then
       echo "REAL FILE (not symlink): $target"
     fi
   done > ~/migration-audit/non-symlink-overrides.txt
   ```
4. For each drifted file, review the diff and decide:
   - Valuable edit → note for reintegration in Phase 29
   - Stale/irrelevant → safe to discard
   - Unknown → flag for manual review
5. Output: `~/migration-audit/dotfiles-drift-diff.txt` and `~/migration-audit/non-symlink-overrides.txt`
