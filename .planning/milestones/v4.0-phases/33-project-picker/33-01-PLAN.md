  <name>Task 1: Create projects.zsh module with pp() function</name>
  <files>dot_zsh.d/projects.zsh</files>
  <action>
Create `dot_zsh.d/projects.zsh` with the full project picker implementation. The file follows the existing module pattern: starts with `# Managed by chezmoi` header, `#!/usr/bin/env zsh`.

**Module structure (top-level declarations then functions):**

1. **Configuration defaults:**
   - `PP_DIRS` array defaulting to `("$HOME/Projects" "$HOME/git")` — hardcoded per user decision
   - `PP_DEPTH` defaulting to `2` (overridable via env var)
   - `PP_EXCLUDES` array: `node_modules .cache vendor target build dist __pycache__`
   - `typeset -ga _PP_CACHE` — session-persistent global array for cache

2. **`_pp_relative_time()` helper:**
   - Takes unix timestamp as `$1`
   - Computes delta from `$(date +%s)`
   - Returns relative string: `Xm ago`, `Xh ago`, `Xd ago`, `Xw ago`
   - Use ZSH arithmetic: `(( delta < 3600 ))` etc.

3. **`_pp_detect_editor()` helper:**
   - Takes repo path as `$1`
   - Detection logic per user decision:
     - `.idea/` present AND `.sublime-project` file found (use `fd -e sublime-project --max-depth 1 . "$1" --quiet 2>/dev/null`) → compare mtime of `.idea/` vs sublime-project file, most recent wins
     - `.idea/` only → `[IJ]`
     - `.sublime-project` only → `[SL]`
     - Neither → empty string (no fallback label shown in list — fallback to Sublime happens only at launch time)
   - Print the label string (e.g., `[IJ]`, `[SL]`, or empty)

4. **`_pp_open_editor()` helper:**
   - Takes repo path as `$1`
   - Same detection logic as `_pp_detect_editor` but returns the command:
     - `.idea/` present (and wins if both) → `idea "$1" & disown`
     - Otherwise → `subl "$1" & disown`
   - Fallback is always Sublime Text per user decision
   - All launches are async (backgrounded + disown)

5. **`_pp_format_line()` — inline xargs worker logic:**
   - Since ZSH cannot `export -f`, the parallel metadata collection must embed all logic in a `zsh -c '...'` string passed to `xargs -P8`.
   - The inline script receives a repo path as `$1` and outputs a pipe-delimited line: `display_text|/absolute/path`
   - Display text format: `printf "%-30s  %-20s  %-40s  %-8s  %s"` with fields:
     - `Parent/name`: strip `$HOME/` prefix, use `dirname`/`basename`
     - `branch*`: `git -C "$1" branch --show-current 2>/dev/null` (fallback `(detached)`), append `*` if `git -C "$1" status --porcelain -uno 2>/dev/null | head -1` is non-empty
     - `~/path`: tilde-prefixed path
     - `Xh ago`: relative time from `stat -f '%m' "$1" 2>/dev/null`
     - `[IJ]`/`[SL]`/empty: editor detection
   - IMPORTANT: The entire logic must be self-contained in the inline zsh string. Do NOT reference any shell functions — xargs workers cannot access them.

6. **`_pp_scan()` function:**
   - Uses `fd` to find `.git` directories under `PP_DIRS`:
     ```
     fd --hidden --no-ignore --type d --max-depth "$((PP_DEPTH * 2))" \
        -E node_modules -E .cache -E vendor -E target -E build -E dist -E __pycache__ \
        "^\.git$" "${PP_DIRS[@]}" 2>/dev/null | sed 's|/\.git/?$||'
     ```
   - Also scans for secondary project markers (package.json, go.mod, Cargo.toml, pom.xml, Makefile, build.gradle, pyproject.toml) in directories that do NOT have `.git/`:
     - Use `fd` with `--max-depth "$((PP_DEPTH * 2))"` for each marker, then filter out directories that already have `.git/`
     - Keep this simple — a second `fd` pass or a find fallback is acceptable
   - Pipes discovered repo paths through `xargs -I{} -P8 zsh -c '...'` using the inline format logic from step 5
   - Output: one `display|path` line per repo

7. **`_pp_build_cache()` function:**
   - Builds sorted list: zoxide frecency first, mtime fallback for untracked repos
   - Step 1: Get zoxide-tracked repos with `zoxide query --list --score 2>/dev/null`, filter to only repos under `PP_DIRS` that have `.git/` or a project marker
   - Step 2: Run `_pp_scan` to get all repos with formatted display lines
   - Step 3: Merge — zoxide-order repos first (re-format display for those), then remaining repos by mtime (newest first)
   - Step 4: Deduplicate by absolute path
   - Store result in `_PP_CACHE` array (each element = `display|/abs/path`)

8. **`pp()` main function:**
   - Lazy cache: `[[ ${#_PP_CACHE[@]} -eq 0 ]] && _pp_build_cache`
   - Build the scan command string for fzf reload (Ctrl+R): store as a local variable that produces the same `display|path` output. On reload, also clear `_PP_CACHE` so next `pp` invocation rebuilds.
   - Run fzf with:
     - `--expect=ctrl-e,ctrl-o` for exit keys
     - `--ansi` for colour support
     - `--delimiter='|'` and `--with-nth=1` to show display text only
     - `--preview='git -C {-1} log --oneline --graph --color=always -15 2>/dev/null'`
     - `--preview-window=bottom,40%,border-rounded`
     - `--header='Enter: cd | Ctrl+E: editor | Ctrl+O: cd+editor | Ctrl+R: refresh'`
     - `--bind="ctrl-r:reload(...)+clear-query"` where the reload command re-runs the scan pipeline. Also set `_PP_CACHE=()` — but since fzf reload runs in a subshell, instead use `--bind="ctrl-r:reload(...)"` and separately arrange for `_PP_CACHE` to be cleared. Simplest approach: on Ctrl+R, just let the reload command regenerate the list inside fzf; after fzf exits, always clear `_PP_CACHE` so next `pp` call rescans. This avoids the subshell limitation.
     - `--layout=reverse-list`
     - Pipe `printf '%s\n' "${_PP_CACHE[@]}"` into fzf
   - Parse result: `key=$(head -1 <<< "$result")`, `path=$(tail -1 <<< "$result" | awk -F'|' '{print $NF}')`
   - Handle empty (Escape): `|| return 0` on fzf exit, and `[[ -z "$path" ]] && return 0`
   - Action dispatch via `case "$key"`:
     - `ctrl-e` → `_pp_open_editor "$path"`
     - `ctrl-o` → `cd "$path" && _pp_open_editor "$path"`
     - `*` (Enter) → `cd "$path"`
   - After fzf exits (regardless of action), clear cache: `_PP_CACHE=()` — this ensures Ctrl+R refresh takes effect on next invocation while keeping the session-lazy-init pattern.

**Style notes:**
- Follow existing codebase conventions: `local` for function-scoped vars, `(( $+commands[...] ))` for command checks, `2>/dev/null` for error suppression
- Use Dracula palette colours via the already-configured `FZF_DEFAULT_OPTS` (inherited automatically — do NOT re-specify colours in `pp`)
- Keep `--preview-window=bottom,40%,border-rounded` matching the Phase 32 convention in `external-sync.zsh`
- No eager computation at source time — only `typeset -ga _PP_CACHE` and `PP_*` defaults run when the module is sourced

**Important:** Do NOT use `export -f` (ZSH does not support it). The xargs inline worker must contain ALL logic as a self-contained zsh script string. Keep it readable with line continuations.

**Performance consideration:** The dirty check (`git status --porcelain -uno`) adds ~11ms per repo. With `xargs -P8` parallelism across 56 repos, total metadata collection is ~230ms. This runs only on first `pp` invocation (lazy cache) or after Ctrl+R refresh. Subsequent `pp` calls use the cached array (instant).
