# Requirements: Dotfiles Stack

**Defined:** 2026-02-15
**Core Value:** Cross-platform dotfiles that "just work" -- one repository that handles Mac vs Linux differences through templating, without requiring Nix expertise to maintain.

## v3.0 Requirements

Requirements for client macOS migration runbook. Each maps to roadmap phases.

### Pre-Migration Audit

- [ ] **AUDIT-01**: User can list all Dotbot symlinks and their targets on the client Mac
- [ ] **AUDIT-02**: User can identify custom scripts/bins in ~/bin and ~/.local/bin not tracked in either repo
- [ ] **AUDIT-03**: User can capture machine-specific env vars and exports unique to the client Mac
- [ ] **AUDIT-04**: User can diff drifted configs against the frozen dotfiles-zsh repo to identify local edits

### Bootstrap

- [ ] **BOOT-01**: User can generate an age encryption key (key-client.txt) and store its public key in Bitwarden
- [ ] **BOOT-02**: User can clone the chezmoi source repo to the client Mac
- [ ] **BOOT-03**: User can run chezmoi init with machine_type=client, work email, and age encryption configured

### Migration

- [ ] **MIG-01**: User can safely remove Dotbot symlinks by first materialising them as real files
- [ ] **MIG-02**: User can run chezmoi apply to deploy all managed files with client-specific templates
- [ ] **MIG-03**: User has a documented procedure for handling conflicts when chezmoi targets already exist

### Reintegration

- [ ] **REINT-01**: User can evaluate custom scripts and decide to add to chezmoi, keep locally, or discard
- [ ] **REINT-02**: User can reintegrate machine-specific env vars into chezmoi templates or a local override file
- [ ] **REINT-03**: User can reconcile drifted config changes by merging valuable edits into chezmoi source

### Verification

- [ ] **VERIF-01**: User can verify shell starts correctly with aliases, prompt, and deferred plugins loading
- [ ] **VERIF-02**: User can verify git workflows (commits, push, mise tasks) function correctly
- [ ] **VERIF-03**: User can verify tool availability (mise runtimes, Homebrew packages, SSH/GPG keys)
- [ ] **VERIF-04**: User can run the smoke test script and all 13 checks pass

### Rollback

- [ ] **ROLL-01**: User has a documented rollback procedure to restore Dotbot symlinks from the old repo
- [ ] **ROLL-02**: User has defined rollback triggers (criteria for bailing vs. debugging forward)

## Future Requirements

None -- this is a one-time migration milestone.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Automated migration script | User wants a runbook they follow manually, not automation |
| Linux server migration | Different machine class; separate milestone if needed |
| Neovim config migration | Intentionally stays outside chezmoi (own repo, documented exception) |
| Deleting old dotfiles-zsh repo | Old repo stays as rollback safety net |
